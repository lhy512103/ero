## 0. 对路线图的修订（动工前确认）

| # | 路线图原文 | 本计划的做法 | 理由 |
| --- | --- | --- | --- |
| 1 | 改性用工艺卡指定配方 | 改性**不用卡**。输入本身已经决定配方；工艺卡只用在「同样的输入能出不同产物」的地方，阶段 2 只有 PLA 牌号一处 | 少一步无意义的操作；卡留给阶段 3 的聚乙烯 / 聚丙烯 |

| 6 | 再生料代数、≤ 30% 掺用 | 阶段 2 只做厂内水口料：水口料 → 塑料粉碎机 → 还原成**原牌号颗粒**，不记代数。代数和掺混比放到阶段 4 回收线 | 掺混比例要追踪每批原料，阶段 2 没有对应玩法 |

| 8 | 电石炉 2 048 EU/t，阶段 2 用 HV | 电石炉最多装 4 个 HV 能源仓，合计 2 048 EU/t | 原文 3.1（HV）和 5.6（2 048）互相矛盾 |

| 10 | 阶段 2 的成型线没有薄膜设备，却要做地膜 | 单螺杆挤出机多一种「吹膜模头」，配一台收卷机 | 否则地膜做不出来 |
| 11 | 炭黑、硫磺 | 阶段 2 用焦粉代替炭黑；硫磺来自焦炉气脱硫。真正的炭黑在阶段 3 随石油出现 | 阶段 2 没有石油 |
| 12 | 公用工程「有就开工」 | 按**台份**计：每台锅炉 / 冷却塔 / 空压机供 N 台机器，超出的机器显示「蒸汽不足：需要 10 台份，现有 8」 | 保留「不精确计量」，又不至于一台锅炉供全厂 |

## 1. 地基（里程碑 M0）

阶段 2 要加约 50 台小机器、5 台大机器、约 30 种流体、约 110 件物品。现有写法每加一台机器要改 12 处 Java（方块、物品、方块实体、菜单、界面、信息面板、指南、Jade、JEI 两处、能量接口、创造栏），照这样做不完。所以 M0 先把「加一台机器」变成「写一份 JSON 加若干配方」。

### 1.1 通用加工机 `machine.process`

| 类 | 作用 |
| --- | --- |
| `ProcessMachineDef` | 一台机器的定义（从 JSON 读） |
| `ProcessMachines` | 启动时读 `iuce/machines/_index.json` 列出的全部定义，循环注册方块、物品、方块实体、菜单；Jade、JEI、指南、能量接口、创造栏全部改为遍历这张表 |
| `ProcessMachineBlockEntity` | 继承 `PoweredMachineBlockEntity`；按定义建物品槽、储罐、模具 / 催化剂槽、工艺卡槽；跑 `iuce:process` 配方 |
| `ProcessMachineMenu` / `ProcessMachineScreen` | 按定义自动排布：左输入、中进度、右产物，储罐竖条，公用工程指示灯，底部状态行 |

定义文件放在 `src/main/resources/iuce/machines/<id>.json`（类路径资源，不是数据包：方块在数据包加载前就要注册）。每份不超过 30 行：

```json
{
  "id": "fermenter",
  "voltage": "LV",
  "buffer": 4000,
  "items_in": 1, "items_out": 1,
  "fluids_in": [16000], "fluids_out": [16000, 8000],
  "catalyst_slot": true,
  "card_slot": false,
  "utilities": ["cooling_water"],
  "upgrades": 4,
  "base_time": 200,
  "model": "tank"
}
```

- `model` 选一种外观模板（`box` 方机 / `tank` 立罐 / `column` 塔 / `kiln` 窑 / `press` 压机 / `cell` 电解槽 / `mixer` 搅拌釜 / `extruder` 卧式）。模板按机器 ID 换前脸贴图，开工时显示动画贴图。
- 存档字段沿用基类（`energy`、`progress`、`maxProgress`、物品），另加 `tanks`、`card`、`recipe`（当前配方 ID，读档时丢弃缓存重新匹配）。
- 物品槽、储罐的输入 / 输出角色由定义决定。`getInputSlots()` / `getOutputSlots()`、`AutomationItemHandler` 和流体接口都按角色开放：输出罐只能抽，输入罐只能灌。

### 1.2 新配方类型 `iuce:process`

现有 `iuce:machine` 的编解码器已经用了 12 个字段（上限 16），只能写两种物品输入，所以另开一个类型，原有配方不动：

```json
{
  "type": "iuce:process",
  "machine": "polymerization_reactor",
  "items": [ { "item": "iuce:lactide", "count": 4 } ],
  "fluids": [ ],
  "catalyst": "iuce:tin_catalyst",
  "card": { "family": "pla", "options": { "grade": "film" } },
  "utilities": ["cooling_water"],
  "segments": [],
  "results": [ ],
  "fluid_results": [ { "fluid": "iuce:pla_melt_film", "amount": 1000 } ],
  "special": {},
  "energy": 6400,
  "time": 200
}
```

| 字段 | 说明 |
| --- | --- |
| `items` | 物品输入，任意个；`item` 或 `tag`，`count` 最大 64；`side: true` 表示必须从侧喂进（双螺杆） |
| `fluids` | 流体输入；`fluid` 或 `tag`（如 `#iuce:any_water` = 水 + 工艺水），`amount` mB |
| `catalyst` | 在场但不消耗的物品（模具、模头、菌种、电极、催化剂）；`damage: n` 表示每次加工扣 n 点耐久，耗尽后变成 `spent_catalyst` |
| `card` | 需要的工艺卡（见 1.4）；省略表示机器里**不能**插卡 |
| `utilities` | 需要的公用工程：`steam` `cooling_water` `compressed_air` |
| `segments` | 只给双螺杆多方块：需要的功能段 |
| `results` / `fluid_results` | 产物，全部确定，**没有概率** |
| `special` | 少数几种需要读写物品属性的规则，见下 |
| `energy` / `time` | 和 `iuce:machine` 一样：单次总耗电、基准 tick |

`special` 只有三种，全部在代码里写死，不做成通用脚本：

- `"color_from": "dye"`：产物颜色取自输入里的染料（色母配方）。
- `"color_from": "input"` + `"result_from_input": 0`：产物就是第 0 个输入本身（只换颜色），着色配方用。
- `"payload": true`：产物（水口料）记下来源颗粒和颜色；塑料粉碎机按记下的来源还原。

匹配规则：

- 机器每次只检查「已插的卡 + 已插的催化剂」对应的配方子集，缓存在 `MachineRecipeCache`。
- 同一台机器、同一张卡下，两条配方的输入不允许互相包含（否则两条都能开工）。这条由校验脚本检查，运行时直接取第一条。
- 配方结果放不下（主产物或任一副产物）时不开工，状态显示是哪一格满了；不会吞掉副产物。

### 1.3 状态原因（可诊断、不惩罚）

机器不开工时，界面底部、Jade 和物流接口的提示里显示同一句原因，按下面的顺序检查第一条：

`no_recipe` 没有匹配的配方 → `no_card` / `wrong_card` → `no_catalyst`（写明缺哪种模具 / 菌种）→ `needs_drying` 料未干燥 → `missing_input` 缺物品 / 缺流体（写明缺什么）→ `missing_utility` 缺公用工程（写明需要几台份、现有几台份）→ `missing_segment` 缺功能段 / `segment_order` 侧喂段在熔融段之前 → `output_full` / `byproduct_full` / `tank_full` → `undervoltage` 电压不足。

### 1.4 工艺卡与工艺设计台

- 物品：`process_card`（空白卡，纸 + 电路板合成，一次 4 张）。写好的卡带物品属性 `iuce:process_card = { family, options }`，名称显示为「工艺卡：聚乳酸 · 薄膜级」。
- 选项来自配方：设计台扫描所有 `iuce:process` 配方的 `card` 字段，按 `family` 汇总出选项表。每个家族最多 2 个选项，每个选项最多 4 档（校验脚本检查）。
- `process_design_table`（工艺设计台，不耗电）：放入空白卡，选家族和选项。右侧实时显示这张卡对应的配方产物、副产物和耗电；点「写入」只消耗空白卡。第二格放一张写好的卡，可以复制。
- 配置器右键可以把一台机器里的卡复制给相邻的同类机器（沿用配置器的批量粘贴）。

### 1.5 流体与气体

- `ModFluids` 改成表驱动：`fluid(id, colour, gas, temperature)` 一行一种。化工流体**没有世界方块、没有桶**，只存在于储罐、管道和容器里。客户端用统一的流动贴图按颜色着色。
- 气体（`#iuce:gases`）只能进机器的气体罐和 `gas_tank`。普通储罐、塑料桶拒收气体，界面提示「需要气体储罐」。
- 流体标签：`#iuce:any_water`（水、工艺水）、`#iuce:gases`、`#iuce:flammable_gases`（可以送火炬或锅炉）、`#iuce:ventable`（可以直接放空）。
- 物品属性：`iuce:color`（16 色）、`iuce:dried`（已干燥）、`iuce:payload`（水口料来源）、`iuce:process_card`。

### 1.6 公用工程（台份制）

- 只走**流体管**网络（见 M9）。管道紧贴机器即可，不需要接口。
- 供方：`boiler` 锅炉（蒸汽，8 台份）、`cooling_tower` 冷却塔（冷却水，8 台份）、`air_compressor` 空压机（压缩空气，8 台份）、余热电站（蒸汽，64 台份）。
- 用方：正在加工、且配方要求该公用工程的机器，每台占 1 台份。
- 网络每 20 tick 汇总一次供需。供不够时按机器坐标排序先到先得，其余显示 `missing_utility`；同样的布局结果永远一样。
- 供方只按实际被占用的台份消耗燃料、水和电，没人用时不耗。
- 测试和创造模式用 `creative_utility_source`（创造栏方块，供三种公用工程各无限台份）。

### 1.7 物流接口支持多储罐机器

现有物流接口只认泵和储罐两种流体角色。M0 给它加第三种 `FLUID_MACHINE`：自动模式下向网络请求机器输入罐缺的流体，把输出罐里的流体交给网络。规则和物品一致。阶段 1 的气动管仍然能运流体（每口 1 000 mB/t），旧存档不受影响。

### 1.8 内容生成脚本 `tools/gen_content.py`

一份机器定义 + 一份内容表（`tools/content/stage2.json`：物品、流体、颜色、中英文名、所属标签）生成：

- 方块状态、方块 / 物品模型、战利品表、`mineable/pickaxe` 标签；
- `zh_cn` / `en_us` 名称（只追加缺的键，不覆盖手写的）；
- 指南的机器页骨架（机器图、`{recipes: 机器}`，说明段落留给手写）；
- 多方块的合并配方（见 M10）；
- `_index.json`。

生成结果入库。脚本重跑后 `git diff` 为空，才算生成器和手改没有冲突。

### 1.9 校验与平衡

`tools/validate_content.py` 增加：

- `iuce:process` 的字段检查：机器存在；配方的物品、流体输入数不超过机器的槽位和罐数；公用工程、功能段名称合法；卡选项不超过 2 × 4。
- 输入互相包含检查（见 1.2）。
- **流体去处**：每种被产出的流体都有消耗它的配方，或者在 `#iuce:ventable`、`#iuce:flammable_gases` 里。
- `STATION`、`USES_*` 改为从机器定义读，不再手抄。
- `MAX_EU_PER_TICK` 按机器电压等级检查，不再是全局 128。

新增 `tools/balance.py`（只用标准库）：

- 按 `tools/content/loops.json` 列出的每条闭环（溶剂、氯碱、氯乙烯回收、工艺水、乳酸母液、电石渣 - 石灰）计算一轮的净补充量，超出声明值就报错。例如己烷类溶剂闭环要求每轮补充 ≤ 3%。
- **刷物检查**：在「主输入 → 主产物」图上找增益大于 1 的环。白名单只有菌种扩培。
- 打印每条产线「1 份原料 → 多少产品、耗电多少、要几台机器配平」的表格，调数值时用。

### 1.10 测试框架

- `ProcessMachineTests`：遍历全部机器定义，每台自动生成 5 项测试（加工、断电、超频、存档往返、缺公用工程），用这台机器的第一条配方。新机器不写测试代码。
- 状态原因测试：每种原因造一个场景，断言显示的文字。
- `LineTests`：每条产线一项整线测试。用代码在测试世界里摆出整条线（机器 + 接口 + 管道），回归专用的注入器每 tick 补原料，跑够时长后断言终端产物数量，并检查闭环里的流体量没有漂移。
- 每个里程碑结束跑一次全量回归 + 一次客户端烟测 + 新指南页截图（GuideShots）。中途只跑与本里程碑相关的测试。

## 2. 内容清单与配方

单位：颗粒「袋」= 1 件物品；流体 mB。电压 LV 32 / MV 128 / HV 512 EU/t。表里写的是「输入 → 产出」，`[ ]` 里是催化剂 / 模具 / 卡，`{ }` 里是公用工程。

### M1 生物路线：糖与乙醇（不需要煤）

新机器：

| ID | 名称 | 电压 | 外观 |
| --- | --- | --- | --- |
| `wet_mill` | 湿磨机 | LV | box |
| `liquefaction_tank` | 液化罐 | LV | tank |
| `saccharification_tank` | 糖化罐 | LV | tank |
| `fermenter` | 发酵罐 | LV | tank |
| `distillation_column` | 精馏塔（小） | LV | column |
| `dehydration_reactor` | 脱水反应器 | MV | tank |
| `dryer` | 干燥器 | LV | box |
| `boiler` | 锅炉 | — | kiln |
| `cooling_tower` | 冷却塔 | LV | column |
| `vent_stack` | 放空火炬 | — | column |

配方：

```
湿磨机     4 土豆 / 小麦（#iuce:starch_crops）+ 1000 水 → 1000 淀粉浆                         100t 16EU/t
湿磨机     4 甘蔗 / 甜菜根（#iuce:sugar_crops）+ 500 水 → 1000 糖液 + 1 蔗渣                   100t 16EU/t
液化罐     1000 淀粉浆 + 1 酶制剂 → 1000 液化醪 {蒸汽}                                          120t 16EU/t
糖化罐     1000 液化醪 → 1000 糖液 [酶制剂 不耗]                                               160t 8EU/t
发酵罐     1000 糖液 → 1000 发酵醪 + 250 二氧化碳 [酵母菌种] {冷却水}                            200t 8EU/t
发酵罐     1000 糖液 → 1000 乳酸发酵液 [乳酸菌种] {冷却水}                                       200t 8EU/t
发酵罐     500 糖液 + 1 小麦 → 2 酶制剂 [曲霉菌种]                                              200t 8EU/t
发酵罐     250 糖液 + 1 菌种 → 2 同种菌种 [同种菌种]（扩培，三种菌种各一条）                       200t 8EU/t
精馏塔     1000 发酵醪 → 500 乙醇 + 500 酒糟液 {蒸汽}                                          160t 24EU/t
脱水反应器 500 乙醇 → 500 乙烯 + 250 工艺水 [活性氧化铝 耗 1] {蒸汽}                             120t 64EU/t
干燥器     1000 酒糟液 → 2 干酒糟 {蒸汽}                                                       100t 16EU/t
锅炉       燃料（煤、焦炭、木炭、蔗渣、干酒糟、重残渣，或可燃气 250 mB）+ 1000 水 → 蒸汽 8 台份，持续按燃料热值
冷却塔     500 水 / 20 秒 + 8 EU/t → 冷却水 8 台份
放空火炬   #iuce:ventable 直接放空；#iuce:flammable_gases 点燃（顶上有火）；其余流体拒收
```

- 菌种来源（工作台合成，只需一次）：酵母 = 棕色蘑菇 + 糖 + 玻璃瓶；乳酸菌 = 牛奶桶 + 糖 + 玻璃瓶；曲霉 = 小麦 + 红色蘑菇 + 玻璃瓶。
- 活性氧化铝：正规配方在 M5（催化剂配制罐，铝粉 + 烧碱液）；M1 先给一个凑合配方：铝粉 ×2 + 水 → 电炉（耐久只有正规版的 1/4）。
- 副产物去处：蔗渣、干酒糟 → 锅炉燃料 + 堆肥桶（数据映射 `neoforge:compostables`）；干酒糟还能喂牛羊（加进繁殖物品标签）；二氧化碳 → 放空火炬；工艺水 → 任何要水的配方（`#iuce:any_water`）。

制品的世界效果：

- **地膜** `mulch_film`（聚乳酸 / 聚乙烯两种）：对耕地使用，变成「覆膜耕地」。覆膜耕地始终湿润，作物随机刻生长 +50%。聚乳酸版在作物收获 8 次后变回普通耕地；聚乙烯版不降解，挖掉时掉落「废地膜」（阶段 4 回收线的原料，阶段 2 可以进锅炉烧）。
- **滴灌管** `drip_pipe`：沿一个方向连成一条，一端要接有水的储罐、泵或流体管；整条管左右各 1 格、沿线全长的耕地保持湿润。用 NeoForge 的耕地湿润接口实现，不改原版代码。
- **流体管**：见 M9。

新物品：7 件中间品（热管坯 ×2、管坯 ×2、热滴灌带、滴灌带、膜泡 ×2、热包覆导线）；`pvc_pipe` `pe_pipe` `pla_film_roll` `pe_film_roll` `drip_pipe` `mulch_film_pla` `mulch_film_pe` `waste_film`；3 种模头 + 模头坯；方块 `mulched_farmland`

**M7 验收（阶段 2 第二个可发布点）**：整线测试，煤 + 盐 + 石灰岩 → 聚氯乙烯管；甘蔗 → 聚乳酸地膜；一条滴灌管让 16 格耕地保持湿润。

## 6. 风险与对策

| 风险 | 对策 |

| 通用机器的界面自动排布不好看 | M0 先排 3 种布局（1 进 1 出、多罐、带模具），用截图确认后再批量套用；特殊机器（设计台、数控加工中心）单独写界面 |
